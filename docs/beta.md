# saborine Beta Operations Kit

本書は、saborine ベータテスト(実カップル5組による7日間の生活テスト+個別インタビュー)の運用キットと、公開に必要な規約類のドラフトである。運営はオーナー1人とAIエージェントを前提とし、読んだその日から使える文面・手順・記入欄を揃えている。規約2本はドラフトであり、公開前に法律の専門家によるレビューを推奨する。

## Overview

このテストで判定する仮説と成功基準は docs/mvp.md の検証計画に従う。仮説1・3・4は提示と質問で測れるため個別インタビューで、仮説2は実生活での行動変化そのものであるため7日間の生活テストで検証する。

| 仮説 | 検証の場 | 対象 | 成功基準 |
| :-- | :-- | :-- | :-- |
| 1 招待: 家事に触れない「里親の手紙」なら、しない側でも招待を受け入れる | 個別インタビュー(手紙カードと受諾画面のモック提示) | しない側条件の10人 | 10人中8人以上が「受ける」、「責められている感じがする」が0件 |
| 2 転換: 感謝を送るだけで始めたしない側が、7日以内に自分から記録する | 7日間の生活テスト | 実カップル5組 | 5組中3組以上で、しない側が7日以内に自発記録を1回以上。途中離脱は1組以下 |
| 3 バランス: バランスで育つ仕組みが、する側の行動を「相手に残す・誘う」に変える | ゲージ2種(合計版・バランス版)の提示 | する側条件の10人(5組のする側5人にDay7インタビューで実施+する側条件の知人5人に個別実施) | 10人中6人以上が「相手の分を残す・誘う」を選び、「監視されているようだ」が0件 |
| 4 促し: キャラクターの促しセリフは、催促や嫌みと受け取られない | セリフ5案の5段階評価(生活テストに相乗り) | しない側条件の10人+5組のしない側5人 | 全採用セリフで嫌み度平均 2.0 以下、やってみたい度平均 3.5 以上 |

配布と収集の前提は次のとおり。Web版(PWA: ホーム画面に追加するとアプリのように使えるWebページ)をURLで配布し、登録は表示名のみとする。集めるデータは表示名・家事記録・ありがとう・通知の宛先情報(Web Push購読情報)の4種類だけである。配信は Cloudflare、データベースは Turso(東京リージョン)を使う。

## Recruiting Kit

### 参加条件(スクリーニング基準)

仮説検証に適した組み合わせは「する側に不満があり、しない側は現状に満足している」という非対称なペアである。両者とも不満なカップルや、両者とも満足なカップルでは仮説2を検証できない。応募窓口はする側とし、スクリーニングの質問はする側にのみ行う(パートナーに先に聞くと先入観を与え、テストが成立しなくなるため)。

カップル5組の採用条件は次のとおり。

| 区分 | 条件 | 理由 |
| :-- | :-- | :-- |
| 必須 | 同棲している(同居カップル・夫婦どちらも可) | 家事の分担が日常的に発生する環境であること |
| 必須 | ふたりとも働いている | ターゲット(共働き)との一致 |
| 必須 | 応募者(する側)は家事分担に不満または軽い不満がある | 仮説の前提となる非対称の片側 |
| 必須 | 応募者から見て、パートナーは現状に不満がなさそう | 非対称のもう片側(大樹型) |
| 必須 | 応募者の体感の家事割合が自分 6:相手 4 以上に偏っている | 偏りが小さいと転換の観察が難しい |
| 必須 | ふたりともスマホでWebとLINEを使える。iPhoneの場合は「ホーム画面に追加」の操作に協力できる | Web Push通知込みの体験を検証するため |
| 必須 | 7日間、生活の中で1日1回程度アプリに触れられる | 生活テストの成立条件 |
| 除外 | 現在、関係が深刻に悪化している(別離を検討中など) | テストが争いの材料になるリスクを避ける |
| 除外 | 家事代行を常用しており家事がほぼ発生しない | 記録する家事が存在しないため |

個別インタビュー10人の採用条件は「しない側」の再現である。同棲・共働きで、家事分担に不満がなく(満足〜どちらでもない)、体感で自分の家事割合が少なめでもそれを問題と感じていない人を集める。所要30分・オンラインで、仮説1(手紙モック)と仮説4(セリフ5案)を実施する。仮説3用のする側条件5人(同棲・共働き・分担に不満あり)も、同じ形式の30分インタビューで別途集める。

スクリーニングは声かけに興味を示した人へ、次の5問を送って判定する。

> 参加できるか確認のため、5つだけ教えてください。
> 1. パートナーと一緒に住んでいますか?
> 2. おふたりとも働いていますか?
> 3. 家事の分担について、あなた自身は今どう感じていますか?(不満がある/少し不満/どちらでもない/満足)
> 4. パートナーの方は、家事の分担についてどう感じていそうですか?(不満がありそう/なさそう/わからない)
> 5. 体感でいうと、家事はあなた:パートナーでどれくらいの割合ですか?(例 7:3)

### 声かけメッセージ(LINEテンプレート)

先入観を防ぐことが最優先である。「家事アプリ」「分担」という言葉を出すと、する側は期待を、しない側は警戒を先に持ってしまい、招待体験(仮説2の入口)が汚れる。プロダクトの説明は「ふたりで使う新しいアプリ」までに留め、パートナーには中身を伏せてもらう。

カップルテスト用(する側になりそうな知人へ)。

> 〇〇、ちょっとお願いがあって!
> いま新しいスマホアプリを作ってて、「ふたり暮らしのカップルが7日間ふつうに生活しながら使ってみる」モニターを探してるんだ。
> ・アプリはURLを開くだけ、登録も1分で終わる(名前を入れるだけ)
> ・7日間、生活の中でちょこちょこ触ってもらう
> ・最後に感想を30〜40分聞かせてほしい
> ひとつだけお願いがあって、パートナーの方には「知り合いのアプリテストに1週間付き合ってほしい。中身は始まってからのお楽しみ」とだけ伝えてもらえる? 先に説明しちゃうとテストにならなくて。
> 興味あったら、確認の質問を5つ送るね!

個別インタビュー用(しない側条件・する側条件の知人へ)。

> 〇〇、30分だけ力を貸してほしい!
> いま作ってるアプリの画面をいくつか見せるので、正直な第一印象を教えてもらうだけのオンラインインタビューです。事前準備はゼロ、正解もなし。思ったことをそのまま言ってくれるのが一番助かる。
> 都合のいい日をいくつか教えてもらえたら嬉しい!

### 参加同意の確認事項

同意はスクリーニング通過後、テスト開始前に両者から取る。しない側にはアプリの中身を明かさずに同意を取る必要があるため、データの扱いと自由に関する事実だけを伝える定型文とする。次の文面をそのままLINEで送り、「OK」の返信をもって同意の記録とする(返信のスクリーンショットを保管する)。

> テストに参加いただく前に、大事なことを5つだけ確認させてください。
>
> 1. アプリに保存されるのは「表示名(ニックネームでOK)・家事をしたという記録・ありがとうを送った記録・通知を届けるための宛先情報」の4つだけです。本名、メールアドレス、電話番号、位置情報は集めません。
> 2. あなたの記録とありがとうは、パートナーの画面に表示されます。運営(私と、開発を手伝うAI)もテスト期間中、動作確認と検証のために記録の内容と日時を見ます。それ以外の目的では見ません。また「どちらが何回やったか」を比べる集計表は作りません。
> 3. 参加はいつでもやめられます。理由を聞いたりしません。やめた場合、データは希望に応じてすべて削除します。
> 4. 最後に感想を聞くインタビューがあります(30〜40分)。メモを取り、同意をもらえた場合だけ録音します。感想を今後の開発資料に使うことがありますが、誰の発言か分からない形にします。
> 5. テスト終了後、データは30日以内にすべて削除します(正式版に引き継ぎたい場合だけ、あらためて確認します)。
>
> この内容でOKなら「OK」と返信してください。質問があれば何でもどうぞ。

謝礼を出す場合は、上記に「お礼として〇〇をお渡しします」を1行追加する。

## Test Operations

### 全体スケジュール

5組は同時開始でなくてよい。各組が Day0〜Day7 の8日間を走り、運営は毎日21時に全組の日次ログを付ける。

| タイミング | やること | 所要 |
| :-- | :-- | :-- |
| 開始前 | 両者の同意取得、パルスアンケート1回目(ベースライン) | 各組10分 |
| Day0 | する側へのセットアップ(下記)。しない側へは何もしない | 各組15分 |
| Day1〜7 毎日21時 | 日次ログの記入(AIエージェントがデータベースから日次サマリーを生成し、オーナーが確認・特記を追記) | 全組で10分 |
| ペア成立時 | しない側へ同意確認の定型文を送る(未送付の場合) | 5分 |
| Day7 | パルスアンケート2回目、クロージングインタビュー(ふたり別々に) | 各組60〜80分 |
| 全組終了後 | 判定シートの記入、次段階の判断 | 60分 |

### Day0: セットアップ

する側とだけ、対面またはビデオ通話で15分のセットアップを行う。手順は次の5ステップである。

1. URLを送り、ブラウザで開いて表示名を登録してもらう。
2. ホーム画面に追加してもらう(iPhone: 共有ボタン→「ホーム画面に追加」)。アプリ内の誘導どおりに進めばよいが、詰まったらここだけは手伝う(通知が届く前提条件のため)。
3. 通知を許可してもらう。
4. その場で実際の家事をひとつ記録し、キャラクターが反応するところまで一緒に確認する。
5. 招待について伝えるのは次の一言だけにする。「パートナーへの招待は、アプリの中に出てくる手紙からできるよ。送るタイミングも、渡し方(LINEで送っても、隣で画面を見せても)も、ぜんぶ自由。今日じゃなくてもいい」

しない側への関与は、招待が自然に起きるかどうか自体が検証対象(仮説2の入口)であるため、意図的に最小にする。運営がやらないことを先に決めておく。

| やらないこと | 理由 |
| :-- | :-- |
| 招待の文面を添削する、送付日を指定する | 招待の切り出しはする側とアプリの手紙カードに委ねる。介入すると招待体験の検証にならない |
| しない側に運営からアプリの説明・使い方のレクチャーをする | 受諾からありがとう送信までをアプリ内の導線だけで完走できるかも検証対象 |
| 期間中に激励・リマインド・「そろそろ記録してみたら」等の働きかけをする | 促しはキャラクターだけが行うという設計原則を運営が破ると、仮説2・4が汚れる |
| 招待が送られない・受諾されない状態を催促する | 未受諾を責めない設計と同じ原則を運営にも適用する。Day3を過ぎても招待が起きない場合は、その事実自体を「招待の障壁」の観察結果として記録する |

しない側への接触は2回だけ許可する。同意確認の定型文(開始前またはペア成立時)と、Day7のインタビュー依頼である。期間中に本人から操作の質問が来た場合は、操作方法のみ答え、家事の話題には触れない。

### 日次の観察とログ

日次ログの目的は、仮説2の成功基準を構成する2つの事実(しない側の自発記録の発生日、感謝の往復の発生)を日付つきで捉えることである。AIエージェントがデータベース(Tursoへの読み取り専用クエリ)から記録・ありがとうの発生日時を日次サマリーとして出力し、オーナーが確認して特記を書き足す。プロダクト原則に合わせ、個人別の累計回数の比較表はテスト運用でも作らない。ログに残すのは「その日に何が起きたか」の事実だけとし、判定シートには発生日のみを転記する。

各組・各日について次の項目を記録する。

| 項目 | 記入内容 | 対応する判定 |
| :-- | :-- | :-- |
| 記録の発生 | する側・しない側それぞれの記録の有無 | 継続状況の把握 |
| しない側の初回自発記録 | この日に初めて発生したら日付に丸。「自発」とは、運営やする側からの依頼なしに自分で記録したもの(依頼の有無はDay7インタビューの質問2で裏取りする) | 仮説2の成功基準そのもの |
| ありがとう | 誰から誰へ送られたか | 報酬の輪の観察 |
| 感謝の往復 | 同じ日のうちに双方向でありがとうが交わされたか | 仮説2の副指標(KPI「感謝の往復率」の初回成立) |
| 離脱兆候 | 両者とも記録・ありがとう・起動が一切ない日が続いているか | 離脱判定の材料 |
| だらしなモード | 発生と復帰の有無 | 罰なし設計の受け取られ方の観察材料 |
| 特記 | 本人からの連絡、通知の不達、不具合など | 定性情報 |

途中離脱の定義は先に決めておく。「どちらかが中止を申し出た」または「3日以上連続で両者とも一切利用がなく、Day7の振り返りにも応じない」場合を離脱1組と数える。どちらかのパルス回答が大きく悪化した場合(後述)は、運営から中止を提案してよい。参加者の関係を守ることをテストの成功より優先する。

### パルスアンケート

アプリの週次パルス(2問アンケート)はベータでは手動運用とする(docs/mvp.md のスコープどおり)。7日間テストでは開始前(Day0まで)と Day7 の2回、各自に個別のLINEで送り、変化を見る。文面は次のとおり。

> アンケート2問だけお願いします。どちらも 1〜5 の数字で返信してください(1=そう思わない、5=そう思う)。この1週間を思い出して答えてください。
> Q1 パートナーに大切にされていると感じた
> Q2 ふたりの家事のやりとりに満足している

集計は次の表に転記する。見方は3つで、(1) する側のスコアが Day7 で上がっているか、(2) しない側のスコアが下がっていないか(アプリが負担になっていないか)、(3) どちらかが 2 点以上下がったペアはインタビューで理由を深掘りし、必要なら中止を提案する。

| 組 | 回答者 | Q1 開始前 | Q1 Day7 | Q2 開始前 | Q2 Day7 | 変化メモ |
| :-- | :-- | :-: | :-: | :-: | :-: | :-- |
| 1 | する側 / しない側 | | | | | |

### Day7: クロージングインタビュー

ふたり同席では本音が出ないため、必ず別々に行う(各30〜40分、オンライン可)。録音は同意を得た場合のみ。質問は10問で、すべて仮説1〜4の判定または安全確認に直結する。〔 〕は対象者を示す。

1. 〔しない側〕招待(サボリーヌの手紙)が届いたとき、正直どう感じましたか。「責められている」という感じは、少しでもありましたか。(仮説1の実地確認)
2. 〔しない側〕初めて自分で家事を記録したときのことを教えてください。何がきっかけでしたか。誰かに頼まれましたか。(記録しなかった場合: 何が止めましたか)(仮説2の判定と自発性の裏取り)
3. 〔しない側〕自分の記録にありがとうが届いたとき、どんな気持ちでしたか。そのあとの行動は変わりましたか。(仮説2の機序確認)
4. 〔する側〕ゲージ(息ぴったり度)を見て、「自分がやろう」と「相手に残そう・誘おう」、どちらの気持ちが強くなりましたか。実際にそうしましたか。(仮説3)
5. 〔両者〕アプリに監視されている、記録を突きつけられている、と感じた瞬間はありましたか。(仮説3の失敗条件と安全確認)
6. 〔しない側〕サボリーヌのセリフを5つ見せます。それぞれ「嫌みに感じる度」と「やってみたくなる度」を 1〜5 で教えてください。(仮説4。セリフ5案は実装から転記して提示する)
7. 〔両者〕この7日間で、ふたりの家事や会話に変化はありましたか。具体的なエピソードがあれば教えてください。
8. 〔両者〕いちばん良かった瞬間と、いちばん面倒・嫌だった瞬間はいつですか。
9. 〔両者〕テストが終わっても使い続けたいですか(1〜5)。その理由は何ですか。
10. 〔両者〕友だちにこのアプリを説明するとしたら、何のアプリだと言いますか。(需要仮説とメッセージングの材料)

## Privacy Policy Draft

> このプライバシーポリシーはベータテスト用のドラフト(下書き)です。法律の専門家によるレビューを受ける前のものであり、法的助言ではありません。

saborine(以下「このアプリ」)は、カップルのおふたりで使うアプリです。運営者〔氏名または屋号〕(以下「私たち」)は、あなたの情報を次のとおり扱います。

### 集める情報

私たちが集めるのは次の4つだけです。

| 情報 | 内容 |
| :-- | :-- |
| 表示名 | あなたが入力した名前。ニックネームでかまいません |
| 家事の記録 | どんな家事をしたかと、その日時 |

### 使いみち

集めた情報は、(1) アプリを動かすこと(パートナーの画面への表示、キャラクターの成長の計算)、(2) 通知を届けること、(3) 不具合の調査とアプリの改善のためだけに使います。広告のために使うことや、外部に売ることはありません。

このアプリは「どちらが何回家事をしたか」を比べる個人別の集計を、画面にも保存データにも作りません。記録がふたりの争いの材料にならないようにするための、このアプリの設計方針です。集計データがそもそも存在しないため、流出したり悪用されたりすることもありません。
